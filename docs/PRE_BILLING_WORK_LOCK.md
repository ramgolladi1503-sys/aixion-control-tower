# Pre-Billing Work Lock

**Status:** Scope lock for engineering work before cloud billing is enabled
**Date:** 2026-10-21
**Product:** Existing Aixion Control Tower repository and Android app

## Purpose

This document locks the work to complete before enabling cloud billing or creating billable cloud resources. It turns the product request into an ordered, testable engineering path. It does not claim that the current repository or local demonstration is production-ready.

## Product contract

The product is a mobile approval console for work already running in a user's native coding-agent session.

1. The user starts work in a supported native agent on their computer.
2. A supported local connector detects an approval pause and sends a scoped request to Control Tower.
3. The Android app presents the exact action, target, risk context, and expiry.
4. An authenticated reviewer approves or rejects that exact request.
5. The connector atomically claims delivery of an approved decision at most once, then returns it to the same paused agent invocation, which continues or stops. An ambiguous/lost claim response fails closed and may require a new invocation.
6. The system records an auditable decision and delivery outcome.

The computer running the agent and connector must remain powered, awake enough to run the task, connected, and authenticated. Cloud hosting can deliver the request and decision while the user is away; it cannot make an offline or terminated local agent resume. Offline, expired, ambiguous, replayed, or mismatched decisions fail closed.

## Locked product decisions

- **Workspace ownership:** one workspace per account for v1. Do not expand to organization workspaces or cross-account sharing in this scope.
- **Client:** the existing Android app is the user-facing approval console. Do not create a separate Mac app or require a Mac app installation.
- **Provider order:** Antigravity is the first real connector target; a Codex approval connector is also required before this pre-billing program is considered complete. Treat each provider as a separately evidenced adapter. In external-agent approval requests, the authenticated `source_agent_id` identifies the registered connector installation; `source_invocation_id` identifies the single gated tool invocation and is included in the frozen approval payload hash.
- **No assumed interception:** do not claim native Codex Desktop approvals can be intercepted until a documented and tested integration proves it. A generic MCP endpoint or simulated approval is not equivalent to resuming a native session.
- **Cloud boundary:** engineering and local verification may proceed without billing. Hosted reachability, real push wake-up, and production deployment remain unverified until a cloud staging environment is authorized and provisioned.
- **No spending:** this lock authorizes no billing activation, payment, paid API enablement, resource creation, deployment, or production data migration.

## Ordered work slices before cloud billing

### Slice 0 — Freeze the approval contract

Write and review a provider-neutral request/decision contract. Bind each request to account/workspace, provider, connector installation, agent session and invocation, exact action payload, risk context, creation time, and expiry. Decisions must be idempotent, single-use, authenticated, auditable, and bound to the exact request version/hash. Define pending, approved, rejected, expired, cancelled, delivery-failed, and consumed states, including race and retry behavior.

**Exit gate:** contract and state transitions are documented; mismatch, expiry, replay, duplicate tap, lost connection, and connector restart behavior are explicit and fail closed.

**Contract clarification (2026-10-22; documentation only):** Clarified that decision retries are effect-idempotent but not response-idempotent (clients reread after an ambiguous response); a committed `CLAIMED` state proves neither connector receipt nor provider execution, and absent a failure report the outcome is unknown; cancellation has no standalone approval route and is authorized only through a linked waiting AgentTask with a conditional race against approval/claim; and a restarted Codex callback with a fresh invocation identity fails closed while the old request remains isolated until expiry. Slice 0 remains accepted for the core contract. No runtime behavior, configuration, schema, or migration changed.

### Slice 2 — Make the connector protocol reliable

Define a versioned connector API with installation identity, short-lived/scoped credentials, rotation and revocation, request correlation, acknowledgements, bounded polling or streaming, reconnect/backoff, and explicit liveness. Ensure the connector can recover outstanding requests after restart without duplicating a decision. An approved decision must be claimed atomically at most once by the owning connector and invocation before the hook returns allow; a duplicate or ambiguous claim fails closed. Add safe diagnostics that exclude secrets and sensitive action contents where not required.

**Exit gate:** contract tests cover timeout, disconnect, reconnect, duplicate delivery, credential revocation, and server restart. No failure mode silently approves or loses the final state.

**Approval-lease upgrade and cutover rule:** Never backfill an invocation lease for a pre-existing native approval from its stored creation time, heartbeat-like metadata, or credential usage. Those values cannot prove that the original native invocation is still paused and waiting. Before enabling lease-gated decisions or delivery during an upgrade, stop creating native pending requests on the old path and drain every existing native invocation approval: let its original connector complete while it can prove liveness, or explicitly reject/expire it through the supported owner flow. If an old request has no verifiable live invocation lease, keep it non-actionable and fail closed; do not synthesize or renew a lease. Record the drain outcome and counts before cutover. This is an operational migration requirement, not authorization to change production data now.
